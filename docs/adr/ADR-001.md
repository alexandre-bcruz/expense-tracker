# ADR-001: Adoption of Event Sourcing + CQRS

## Status
Accepted

## Context
This is a personal portfolio project (expense tracker), not a production
system with real scale or multiple users.

## Decision
We adopt Event Sourcing + CQRS, even though it is architecturally more
complex than this domain strictly requires.

## Motivation
The primary goal of this project is to demonstrate hands-on proficiency
with Event Sourcing and CQRS for a technical portfolio, targeting senior
backend roles in event-driven and distributed systems. These patterns are
common in domains that require immutable audit trails, historical
reconstruction of state, and clear separation between write and read
models — such as financial systems, e-commerce order processing, or
compliance-heavy platforms — even though this specific expense tracker
does not have those requirements at its current scale.

## Trade-offs Accepted
- Increased complexity: event store, projections, eventual consistency.
- Overhead not justified by current scale or usage.
- Chosen deliberately, as a portfolio decision rather than a production
  necessity.

## Consequences
The README and this ADR make this trade-off explicit rather than hiding
it, framing the project as a demonstration of patterns typical in
production financial and compliance-heavy systems.
